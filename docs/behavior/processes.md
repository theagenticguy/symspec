# symspec · Processes

What actually runs when the key operations execute. Each step cites the source line (`path:LINE`) that performs it. Branch points — opt-in flags, gate exclusions, and error paths — are called out inline. As of v3, `check` also runs an always-on deterministic ambiguity family and a numeric/arithmetic conflict tier, plus opt-in bounded temporal and semantic/graph tiers; those tiers are covered below.

## Parse a line (Tier 1 → Tier 2 → Tier 3 ladder)

One line is driven by `parseLine` (`src/parse/result.ts:258`), which calls `runTier2` then `resolveParseResult`. Batch input fans out over the same driver, line by line, so the wink model loads at most once (`src/parse/batch.ts:157`, `src/parse/batch.ts:160`).

1. **Tier 1 — regex cascade (`classifyTier1`, `src/parse/tier1.ts:221`).** `preprocess` normalizes the line; an empty result escalates immediately (`src/parse/tier1.ts:240`). The ordered cascade `ORDER` is tried rung by rung: complex → unwanted (if…then) → event (when / no-comma) → state (while) → optional (where) (`src/parse/tier1.ts:239`, loop at `src/parse/tier1.ts:243`). Order is load-bearing: `complex` precedes `state`, `if…then` precedes `when`.
2. **Main-clause gate.** A rung is matched only when its main clause parses via `MAIN` (`parseMain`, `src/parse/tier1.ts:156`). A keyword match whose `<system> shall <response>` does not parse is NOT a partial success — it falls through to the next rung (`src/parse/tier1.ts:247`). Falling off the cascade, a bare main clause becomes `ubiquitous` (`src/parse/tier1.ts:263`).
3. **Tier-1 confidence + hard escalation.** `buildResult` (`src/parse/tier1.ts:282`) runs `systemEscalationNotes` over the recovered subject (`src/parse/tier1.ts:192`); a hard trigger (comma / embedded EARS keyword / >6 tokens) turns the parse into a MISS rather than a garbage slot set (`src/parse/tier1.ts:292`). Soft signals downgrade confidence: a non-`shall` modal downgrades to `medium` and notes `nonstandard-modal`; a person-word subject (`weak-subject`) downgrades to `low` (`src/parse/tier1.ts:199`). A modal-bearing line with no response becomes `modal-without-response`; a truly modal-free line becomes `no-main-clause` (`src/parse/tier1.ts:275`, `src/parse/tier1.ts:279`).
4. **Escalation decision (`escalationTriggers`, `src/parse/tier2.ts:196`).** Whole-sentence checks fire independent of the Tier-1 verdict: >60 tokens (`MAX_TIER1_TOKENS`) → `long-sentence`; a top-level `and`/`or` → `compound-conjunction` (`src/parse/tier2.ts:205`). A Tier-1 miss adds `no-rung-matched` and returns (`src/parse/tier2.ts:208`). On a usable Tier-1 parse, soft signals ride along: `weak-subject`, `passive-main-clause`, `nested-clause-keyword` (`src/parse/tier2.ts:216`).
5. **Tier-2 gating (`runTier2`, `src/parse/tier2.ts:513`).** When NO trigger fires the line is clean: it returns `{ escalated: false }` WITHOUT invoking the loader, so the ~4.5 MB wink-nlp model is never imported on the fast path (`src/parse/tier2.ts:521`). When a trigger fires it lazily loads the analyzer via `opts.load` (default `defaultTier2Loader`, which dynamic-`import()`s `wink-nlp` + `wink-eng-lite-web-model`) (`src/parse/tier2.ts:521`, `src/parse/tier2.ts:272`). A loader failure yields a Tier-2 miss with `tier2-load-failed` — it never throws, so the ladder can still reach Tier 3 (`src/parse/tier2.ts:525`).
6. **Tier-2 repair (`repairWithWink`, `src/parse/tier2.ts:423`).** Pivots on the first modal (by lemma/surface membership, not POS, so a passive `be` is never mistaken for a modal) to rebuild `systemName` from the contiguous UPOS noun-chunk to its left and `systemResponse` from everything to its right (leading negator extracted to a polarity flag) (`src/parse/tier2.ts:432`, `src/parse/tier2.ts:437`, `src/parse/tier2.ts:453`). A leading EARS keyword before the subject is recovered into `preCondition`/`trigger` (`src/parse/tier2.ts:463`). Tier 2 is a repair tier: confidence is never `high` — any repair note or soft trigger pins it to `low`, else `medium` (`src/parse/tier2.ts:481`).
7. **Resolve the outcome (`resolveParseResult`, `src/parse/result.ts:231`).** A `compound-conjunction` trigger FORCES a Tier-3 `ERR_PARSE_COMPOUND` error even over a nominal Tier-1/Tier-2 ok — the recovered slots survive in `partial` (`src/parse/result.ts:232`). Otherwise it prefers a Tier-2 repair, then a usable Tier-1 parse (`src/parse/result.ts:234`); failing both, it falls to Tier 3.
8. **Tier 3 — error envelope (`makeTier3Envelope`, `src/parse/tier3.ts:283`).** Aggregates notes/triggers from both tiers, assigns an `ERR_PARSE_*` code by priority COMPOUND > NO_MODAL > NOT_A_REQUIREMENT > AMBIGUOUS_CLAUSES (`assignCode`, `src/parse/tier3.ts:222`), and attaches mechanical rewrite suggestions plus best-effort `partial` slots. `fromTier3` then draws the skipped/error boundary: `ERR_PARSE_NO_MODAL` becomes `outcome: 'skipped'` (no-modal prose, not an error), every other code stays `outcome: 'error'` (`src/parse/result.ts:206`).

## `check` end-to-end

The orchestrator is `runCheck` in `src/pipeline/check.ts:678` (the file grew ~490 LOC under issue #2). It assembles structural, lint, ambiguity, and formal findings into one `CheckReport`, computes the `verified` verdict, and never touches the Lean tier — the import list at `src/pipeline/check.ts:56` carries no `../certify/*` (the AC-5-5 invariant). The load-bearing rule is `verified = demotions.length === 0` (`src/pipeline/check.ts:1289`): a propose-only signal or coverage stat can only push `verified` toward FALSE, never toward TRUE (demotion-only; see below). Steps run in this order:

1. **List requirements.** `listRequirements(doc)` snapshots the stored requirement set (`src/pipeline/check.ts:679`).
2. **Tier 0 — structural.** `normalizeStructural(analyze(doc))` runs the dangling-ref / missing-slot / cycle / orphan / leaf-unverifiable checks and maps each `Finding.kind` to its `FND_*` code via `structuralKindToFndCode`, assigning severity from `STRUCTURAL_SEVERITY` (`src/pipeline/check.ts:682`; normalizer at `src/pipeline/check.ts:620`, severity map at `src/pipeline/check.ts:604`).
3. **Lint — GtWR.** `normalizeLint` renders each requirement's sentence, then runs the per-statement `checkGtWRules` and set-level `checkGtWRulesSet` (~24 GtWR rules), each finding carrying its span and optional rewrite suggestion (`src/pipeline/check.ts:685`, `src/pipeline/check.ts:633`).
4. **Ambiguity family — always-on, deterministic.** `detectAmbiguity(requirements.map(asView))` runs the vague/quantifier/reference detectors plus the structured contextual-ambiguity punt, and each finding is pushed as a `lint`-tier `FND_AMBIGUOUS_*` / `FND_AMBIGUITY_NEEDS_JUDGMENT` (`src/pipeline/check.ts:691`; detector at `src/formal/ambiguity.ts:442`). Pure and synchronous — no solver, no model — so it runs on the default path like structural + lint. Only the mechanical `and…or` coordination case is `warn` (verdict-eligible); everything else is `info` propose-only (`src/formal/ambiguity.ts:40`).
5. **AC-3-7 gate — partition before symbolization.** `gateRequirements(requirements, doc.waivers ?? [])` splits the set and `excludedIds` builds the exclusion membership set (`src/pipeline/check.ts:708`, `src/pipeline/check.ts:709`). This runs BEFORE the formal tier so the SMT layer never receives unsound input, and it is now **waiver-aware** — a committed waiver on a formal-blocking lint re-admits its requirement to the solver (see the gate process below).
6. **Free tier + formal tier via the solver orchestrator.** `runSolvers(doc, {…})` runs the free tier (exact-duplicate detection, candidate-pair generation) and then calls the injected `formal` callback with `{ reqs, pairs }` (`src/pipeline/check.ts:730`; orchestrator at `src/solvers/index.ts:68`). The formal callback captures its rich findings into the `formal` closure array and returns `{ findings: [], pairsChecked }` so nothing is double-counted (`src/pipeline/check.ts:716`, `src/pipeline/check.ts:1004`).
7. **Inside the formal callback — exclude, then encode once.**
   - Filter the gate's excluded ids out of `reqs` to get `included`; project each to `EncodableRequirement` via `toEncodable` (resolves negation — see below) (`src/pipeline/check.ts:735`, `src/pipeline/check.ts:737`).
   - Build the atomizer over the committed glossary AND the committed antonym index (`makeAtomize(glossaryIndex(doc.glossary), docAntonymIndex(doc))`, empty ⇒ seed-only behavior) (`src/pipeline/check.ts:746`; antonym index at `src/pipeline/check.ts:546`).
   - Boot the shared Z3 WASM context `getContext('symspec-check')` and encode every included requirement once into `EncodedRequirement`, indexed by id (`src/pipeline/check.ts:751`, `src/pipeline/check.ts:752`).
   - Build the spec-wide atom→owners roster (an atom is "matched" only when ≥2 distinct requirements reference it; singletons feed both coverage and the relational detector) (`src/pipeline/check.ts:762`), then restrict the free tier's candidate `pairs` to pairs where both ids are included (`src/pipeline/check.ts:779`).
8. **Formal SMT checks over the gate-INCLUDED set (run in this order).**
   - `findContradictions(encodable, {atomize, timeoutMs})` — per-context-group reachability, default `timeoutMs` 2000 (`src/pipeline/check.ts:781`, `src/pipeline/check.ts:739`).
   - `checkSubsumption(ctx, encodedById, includedPairs)` — pairwise (`src/pipeline/check.ts:782`).
   - `checkVacuity(ctx, encoded)` — whole-spec (`src/pipeline/check.ts:783`).
   - `checkCompleteness(ctx, encoded)` — whole-spec completeness heuristic → `FND_INCOMPLETE` (`src/pipeline/check.ts:784`).
   - `findSimilarUnunified(encodable, …)` — lexical similar-but-ununified (`src/pipeline/check.ts:785`).
   - `findNeedsReview(encodable, {atomize, timeoutMs, solverBudgetMs?})` — per-group `unknown`/timeout upgraded to `FND_NEEDS_REVIEW`; honors the whole-run `solverBudgetMs` boundary when supplied (`src/pipeline/check.ts:791`).
9. **Numeric/arithmetic conflict tier — over ALL requirements.** `extractNumericPredicates` lifts unit-normalized `(quantity, comparator, value)` predicates from each requirement's response, trigger, and precondition, keyed through the committed glossary as a quantity-alias map (`src/pipeline/check.ts:809-821`; extractor at `src/formal/numeric.ts:231`), and `findNumericContradictions(ctx, numericReqPreds)` proves any same-quantity set jointly unsatisfiable over LIA/LRA on the shared context, emitting `FND_NUMERIC_CONTRADICTION` (`src/pipeline/check.ts:822`; solver at `src/formal/numeric-contradiction.ts:55`). Runs over ALL requirements, NOT the gate-included subset — numeric conflict is independent of propositional-encoding soundness, so a lint-blocking finding must not hide a real numeric contradiction (rationale at `src/pipeline/check.ts:797`). The quantity KEY deliberately keeps trailing comparator words rather than stripping them, because there is no sound way to tell a leaked compound-bound word from a phrasal-verb noun tail — stripping fabricated a false contradiction (the cardinal sin), so that case is instead surfaced propose-only (`src/formal/numeric.ts:211`).
10. **PROPOSE-only cross-requirement signals — over ALL requirements.** Two demotion-only detectors run right after the numeric tier, reusing the predicates and atom roster already built:
    - `findQuantityAliasCandidates` flags same-system + same-trigger opposed numeric bounds whose labels share an object but differ in leading verb — so they atomized to different quantity keys and were never compared — and emits an `info` `FND_QUANTITY_ALIAS_CANDIDATE` carrying the exact `symspec glossary add "<a>" "<b>"` command to route both phrasings to one key (`src/pipeline/check.ts:835`; detector at `src/formal/quantity-alias.ts:160`). It only PROPOSES, so lenient object-matching is sound here.
    - `findRelationalUnchecked` detects the structural SHAPE where aggregate/conservation or emergent-structural conflicts hide (≥2 numeric-bounded members with a singleton atom, or ≥2 members with inter-entity comparison language, under one shared trigger) and emits `FND_RELATIONAL_UNCHECKED` with an honest "reasoning not attempted" caveat (`src/pipeline/check.ts:856`; detector at `src/formal/relational.ts:100`). It NEVER asserts a conflict, so it cannot fabricate one.
11. **Opt-in bounded temporal tier (`--temporal`) — over ALL requirements.** Only when `options.temporal` is set: each requirement maps to LTL via `earsToTemporal` (Dwyer/FRET patterns) and `findTemporalContradictions(ctx, …, bound ?? 10)` proves temporal contradictions via bounded LTL→SMT on the shared Z3-WASM context, emitting `FND_TEMPORAL_CONTRADICTION` (`src/pipeline/check.ts:871`; solver at `src/formal/temporal.ts:118`). Sound-for-UNSAT, NOT complete-for-SAT — a `sat` result at the bound is not a consistency certificate; evidence carries `{bound, complete:false}`.
12. **Opt-in semantic + opposition + graph passes (`--semantic`) — over the INCLUDED set.** Only when `options.semantic` is provided: `findSimilarSemantic` proposes `FND_SIMILAR_SEMANTIC` glossary merges (default cosine 0.82) (`src/pipeline/check.ts:884`); `findOppositionCandidates` proposes `FND_OPPOSITION_CANDIDATE` for same-system responses sharing an object but differing on verb and not already antonyms, suggesting `symspec antonym add` (`src/pipeline/check.ts:899`); `buildSimilarityGraph` proposes `FND_MISSING_TRACE_LINK` and `FND_DUPLICATE_CLUSTER` over a deterministic kNN graph (`src/pipeline/check.ts:914`; graph at `src/formal/graph.ts:102`). All reuse the same injected embedder, all propose-only (info), never a verdict. Off by default, so the base path never loads the embedding model.
13. **Attach evidence + push.** `attachEvidenceToAll([...contradictions, ...subsumptions, ...vacuities], encodedById)` decorates the unsat-triggered findings with the atom table + core (`src/pipeline/check.ts:930`). Those are pushed with `evidence`; `incompletes`/`similar`/`review`/`semantic`/`graph`/`opposition`/`quantityAliasCandidates` are pushed without (`src/pipeline/check.ts:946`). Numeric, temporal, and relational-unchecked findings are pushed separately with their own tier-specific shape (`src/pipeline/check.ts:967`, `src/pipeline/check.ts:979`, `src/pipeline/check.ts:993`).
14. **Free-tier projection.** Back in `runCheck`, exact-duplicate free-tier findings become `FND_EXACT_DUPLICATE` lint findings; the free-tier weasel `Ambiguity` projection is dropped because GtWR already covers those lexicons with stable codes (`src/pipeline/check.ts:1010`).
15. **Loud lint→formal exclusion.** One `FND_EXCLUDED_FROM_FORMAL` info finding is emitted per requirement the gate dropped, tagged `structural`, so a coverage hole the solver never saw is visible in `findings[]` rather than buried in a count (`src/pipeline/check.ts:1030`; finding builder at `src/formal/coverage.ts:59`). This closes the "0 contradictions, verified:true, over an unchecked third of the doc" trap.
16. **No-pairs disclosure.** `FND_NO_PAIRS_CHECKED` fires when `pairsChecked === 0` over ≥2 requirements AND no cross-requirement finding fired — but `crossRequirementFired` deliberately does NOT count the coverage-gap codes (`COVERAGE_GAP_FND_CODES`), because each of those signals a comparison did NOT happen (`src/pipeline/check.ts:1085`, `src/pipeline/check.ts:1096`; set at `src/pipeline/check.ts:441`).
17. **Waiver drop, then tally.** Findings suppressed by a committed waiver are dropped BEFORE the counts and the `verified` computation, so the exit gate and verdict both honor the waiver (`src/pipeline/check.ts:1114`; `isWaived` at `src/pipeline/check.ts:453`). `counts` tallies the kept findings by severity (`src/pipeline/check.ts:1123`).
18. **Compute `verified` (demotion-only).** Every reason `verified` is false is pushed into `demotions[]` with its discharging action: uncovered (all-singleton) requirements, `excluded-from-formal` (keyed off `gateResult.excluded`, the structural fact — NOT the post-waiver set), `quantity-alias-candidate`, `relational-reasoning-not-attempted`, `open-opposition-candidate`, `no-decide-tier-comparison`, and `semantic-tier-skipped` (`src/pipeline/check.ts:1200-1288`; reason union at `src/pipeline/check.ts:252`). Then `verified = demotions.length === 0` (`src/pipeline/check.ts:1289`).
19. **Assemble the report.** Sort with `compareFindings` (severity rank → code → first requirement id), build the `CoverageReport` (`requirements`, `openOppositionCandidates`, `demotions`, `encoded`, `excluded`, `pairsCheckedNote`), roll up `residualRisk`, resolve the opt-in `strictGate`, and return the whole `CheckReport` with `verified` (`src/pipeline/check.ts:1301`, `src/pipeline/check.ts:1339`; comparator at `src/pipeline/check.ts:665`).

**Negation resolution (`toEncodable`, `src/pipeline/check.ts:570`).** The persisted `negated` flag is authoritative: when set, the stored `systemResponse` is already the positive atom and passes through with `negated: true` (`src/pipeline/check.ts:571`). Only when the flag is absent does a conservative leading-negator scan strip a baked-in negator and set `negated: true` (`src/pipeline/check.ts:572`).

**CLI wiring (`src/cli/index.ts:444`).** The `check` action loads the doc, then (only on `--semantic`) lazily imports and calls `loadEmbedder`, surfacing a load failure as `ERR_EMBED_MODEL_MISSING` before any tier runs (`src/cli/index.ts:543`, `src/cli/index.ts:552`). It calls `runCheck` (`src/cli/index.ts:594`), optionally output-shapes via `filterReport`, and optionally exports the portable `.smt2` artifact (`--emit-smt2`) or cross-checks against an external z3/cvc5 binary (`--solver z3-bin|cvc5`), both re-using `encodeIncluded(doc)` — which applies the SAME waiver-aware gate so the artifact matches what `check` evaluated (`src/cli/index.ts:611`, encoder at `src/pipeline/check.ts:590`). Finally `emit(success('check', report))` maps to the exit code via `exitCodeForEnvelope` (`src/cli/index.ts:632`; exit at `src/cli/index.ts:161`).

## The PROPOSE / DECIDE two-pass author loop

The doctrine's spine: a fuzzy signal can only PROPOSE; only a committed, agent-reviewed artifact that the sound SMT layer consults can DECIDE. `FND_QUANTITY_ALIAS_CANDIDATE` (`src/formal/quantity-alias.ts:160`) and `FND_RELATIONAL_UNCHECKED` (`src/formal/relational.ts:100`) are the two propose-only signals added under issue #2; both belong to `PROPOSE_ONLY_FND_CODES` (`src/pipeline/check.ts:413`), so they DEMOTE `verified` but never establish it.

The reproducer-a pass proves the loop closes on a real z3 proof:

1. **Pass 1 — abstain.** A spec states one physical quantity two ways ("complete the infusion within ≤30 min" vs "run the infusion for ≥60 min"). The numeric tier keys the quantity off the noun phrase before the comparator, so the two verb-phrasings split onto different keys and the joint bound is never compared. `findQuantityAliasCandidates` fires the high-precision candidate — same system, same trigger, shared object suffix, differing leading verb, opposed comparators, comparable unit (`src/formal/quantity-alias.ts:174-215`) — which pushes a `quantity-alias-candidate` demotion so `verified` is FALSE, and the finding's message carries the exact `symspec glossary add "infusion within" "run the infusion"` command (`src/pipeline/check.ts:1234`).
2. **Commit the DECIDE-tier artifact.** The author runs `glossaryAdd(doc, canonical, alias)` (`src/cli/glossary.ts:58`), routing both phrasings under one canonical key. This is the only step that changes the verdict surface, and it is agent-reviewed.
3. **Pass 2 — prove.** On re-run, `glossaryIndex(doc.glossary)` is passed as the numeric quantity-alias map (`src/pipeline/check.ts:809`), so `quantityKey` canonicalizes both labels to one key (`src/formal/numeric.ts:170`). The LIA/LRA solver now sees both bounds on one quantity and proves `FND_NUMERIC_CONTRADICTION` (≤30 ∧ ≥60 UNSAT) naming both requirements. The candidate stops firing because the labels no longer differ. This exact abstain→commit→prove path is a regression fixture (`adversarial/eval-rounds.ts:589`).

The intractable case (reproducer b — odd-cycle 2-coloring: five sensors in a ring each required to differ from a neighbor over two channels) has no sound NL extractor, so `findRelationalUnchecked` DEMOTES with a `relational-reasoning-not-attempted` caveat and the tool declines to certify rather than certify a lie (`adversarial/eval-rounds.ts:610`).

## Pipeline gate — waiver-aware exclusion before symbolization (AC-3-7)

`gateRequirements` in `src/pipeline/gate.ts:164` wraps `gate` (`src/pipeline/gate.ts:134`) and partitions a requirement set into `included` (safe to hand the formal encoder) and `excluded`. Deterministic and I/O-free. Both now take an optional `waivers` list (default empty ⇒ the exact pre-feature partition).

1. **Per requirement, parse-failure short-circuit.** If the caller marks `parseFailed: true`, the requirement is excluded with reason `'parse-failure'` and no surface check runs (`src/pipeline/gate.ts:139`). No current caller wires parse outcomes through here; `gateRequirements` omits the flag (`src/pipeline/gate.ts:169`).
2. **Waiver-aware blocking surface check.** Otherwise `blockingFindings(requirement, waivers)` renders the sentence, runs the GtWR lint, and keeps ONLY `error`-severity findings that are NOT waived — the legitimate-exception rules land at `warn`/`info` and must never exclude a statement, and a committed waiver on a blocking lint drops it from the blocking set (`src/pipeline/gate.ts:98`, `src/pipeline/gate.ts:101`, `src/pipeline/gate.ts:144`).
3. **Exclude or include.** Any surviving blocking finding excludes the requirement with reason `'blocking-surface-check'`, carrying those findings as evidence; zero blocking findings (including one whose only blocking lint was waived) re-admits it to the formal tier (`src/pipeline/gate.ts:145`, `src/pipeline/gate.ts:150`).

The excluded set feeds `runCheck`'s formal filter (`src/pipeline/check.ts:735`) and drives the `FND_EXCLUDED_FROM_FORMAL` disclosure + `excluded-from-formal` demotion off `gateResult.excluded` (the structural fact), so waiving the DISCLOSURE alone can never restore coverage — only waiving the underlying blocking lint (which re-admits the requirement) or rephrasing it does (`src/pipeline/check.ts:1219`). The numeric, temporal, and relational tiers run over ALL requirements and are NOT restricted to this included subset (`src/pipeline/check.ts:809`, `src/pipeline/check.ts:856`, `src/pipeline/check.ts:871`).

## Formal SMT contradiction check

`findContradictions` in `src/formal/contradiction.ts:229`. Async because the solver call is the only asynchronous boundary; everything up to `check` is deterministic.

1. **Guard clause.** Fewer than 2 requirements → `[]` (`src/formal/contradiction.ts:233`).
2. **Encode once.** Each requirement is encoded into its guarded-implication formula `REQ-i ⇒ (context ⇒ response)` via `encode` (`src/formal/contradiction.ts:238`; encoder at `src/formal/encode.ts:205`). The body is derived from the slots actually present, so an event-driven requirement carrying a precondition correctly encodes as `(P ∧ T) ⇒ R`.
3. **Boot Z3 + materialize.** `getContext('symspec-contradiction')` then `materialize` lowers each formula to a Z3 `Bool`; Z3 interns Bool consts by name so ASTs are reusable across the fresh Solver built per group (`src/formal/contradiction.ts:239`, `src/formal/contradiction.ts:244`). Each requirement's guard is a Bool const named after the id — that lookup is the structural CTX-* filter.
4. **Plan context groups (`planContextGroups`, `src/formal/contradiction.ts:140`).** The distinct context-atom sets across the spec, plus one always-first baseline empty-context group so unconditional (ubiquitous-vs-ubiquitous) conflicts are checked even for an all-ubiquitous spec. Mutually exclusive triggers land in DISTINCT groups so they are never asserted together and cannot fake a conflict.
5. **Per-group reachability check.** For each group: a fresh Solver with `timeout` (default 2000 ms) and the z3-only `smt.core.minimize` option; assert EVERY requirement's whole-spec formula, then `add()` the group's context atoms as PLAIN assertions so they can never appear in the core (`src/formal/contradiction.ts:258`, `src/formal/contradiction.ts:265`).
6. **Enumerate disjoint conflicts.** With the guards as the ONLY assumption literals, loop `solver.check(...assumptions)` while ≥2 assumptions remain. `unknown`/timeout is never "no conflict" — it breaks the group's enumeration (upgraded elsewhere to `FND_NEEDS_REVIEW`) (`src/formal/contradiction.ts:282`). On `unsat`, filter the raw core to guard literals; drop that core's guards and re-check for the NEXT disjoint conflict (`src/formal/contradiction.ts:293`).
7. **Unsat-core minimization (`minimizeCore`, `src/formal/contradiction.ts:189`).** Deletion-based: for each candidate guard, re-check with it dropped; if still `unsat` the guard was inessential and is removed permanently; `sat`/`unknown` keeps it. Stops before dropping below a pair.
8. **Emit.** A minimized core of ≥2 unique ids becomes one `FND_CONTRADICTION` (severity `error`), deduplicated by sorted id-set key across groups (`src/formal/contradiction.ts:309`). A degenerate single-id core is skipped. A contradiction is detectable only when two responses resolve to the same atom with opposite polarity — conflicts across unrelated atoms are a documented false negative (sound modulo atomization).

## Add / update a requirement (the `applyChange` mutation path)

`applyChange` in `src/core/changes.ts:74` (216 LOC) is the ONLY sanctioned way to mutate a requirements document. It takes the current plain-object `RequirementsDoc`, validates a raw `Change` against `ChangeSchema`, `structuredClone`s the input, and returns a NEW document with the change applied — the input is never mutated (`src/core/changes.ts:75`, `src/core/changes.ts:77`).

1. **`add` command core (`runAdd`, `src/cli/add.ts:121`).** Requires exactly one of `--from-parse "<prose>"` or structured EARS slots (`src/cli/add.ts:129`). On the prose path it calls `parseLine` (`src/cli/add.ts:151`): a Tier-3 `error` surfaces the stable `ERR_PARSE_*` code + `partial` + suggestions verbatim (`src/cli/add.ts:152`); a `skipped` no-modal line becomes `ERR_PARSE_NO_MODAL` (`src/cli/add.ts:164`); an `ok` parse threads the parse tier's `negated` flag into the create attrs (`src/cli/add.ts:185`). The id is `args.id ?? newId()` (`src/cli/add.ts:200`).
2. **CreateRequirement (`src/core/changes.ts:80`).** `applyChange` throws a typed `ChangeError` with code `ERR_DUPLICATE_ID` if the id already exists (`src/core/changes.ts:82`); otherwise it builds the node, persisting the `negated` flag and threading it into `renderSentence` so the stored `sentence` reads "shall not <response>", and defaulting `priority`/`status` and empty edge arrays (`src/core/changes.ts:95`, `src/core/changes.ts:102`). Optional slots (`preCondition`/`trigger`/`verificationMethod`) are assigned only when defined (`src/core/changes.ts:119`).
3. **`update` command core (`runUpdate`, `src/cli/update.ts:104`).** Requires exactly one of a `<value>` or `--clear` (`src/cli/update.ts:108`). Before mutating, it blocks clearing a slot the requirement's own pattern needs, returning a typed `ERR_NULL_REQUIRED` envelope so a malformed sentence is never persisted (`src/cli/update.ts:137`), then calls `applyChange` with `value: clearing ? null : value` (`src/cli/update.ts:154`).
4. **UpdateAttribute (`src/core/changes.ts:127`).** A missing id throws; `null` clears an optional (`NULLABLE_ATTRS`) attr but throws `ERR_NULL_REQUIRED` on a required attr (`src/core/changes.ts:136`); any of the five EARS structural slots (`patternType`/`preCondition`/`trigger`/`systemName`/`systemResponse`) re-renders `sentence`, while a pure metadata edit (priority/status/verificationMethod) does not (`src/core/changes.ts:153`).
5. **Edge ops.** `AddRelationship` is idempotent — it no-ops when the edge already exists but throws when the source id is missing (`src/core/changes.ts:174`); `RemoveRelationship` and `DeleteRequirement` are no-ops on a missing edge / requirement (`src/core/changes.ts:187`, `src/core/changes.ts:202`). `applyChanges` threads a sequence left-to-right (`src/core/changes.ts:212`).
6. **Persist atomically.** The CLI `add`/`update` actions call `saveOrEmit` on the returned `next` document (`src/cli/index.ts:231`, `src/cli/index.ts:263`; def at `src/cli/index.ts:843`), which calls `writeDocFile` (`src/core/storage.ts:135`). The write is atomic: `atomicWriteFile` writes to a sibling temp file then `rename`s it into place, unlinking the temp on failure (`src/core/storage.ts:109`, `src/core/storage.ts:121`). Any I/O failure lifts to an `ERR_IO` envelope (`src/cli/index.ts:847`).

## `certify` (Lean, opt-in, off the check path)

The optional Lean tier, entirely separate from `check`. `certify` in `src/certify/run.ts:305` is the full pipeline; discovery is a caller-side precheck. The CLI `certify` command is the ONLY command that touches `src/certify/*` (`src/cli/index.ts:439`).

1. **Discover the toolchain (`discoverLeanToolchain`, `src/certify/discover.ts:72`).** Synchronously `spawnSync('lean', ['--version'])`. A spawn error (e.g. ENOENT) or non-zero exit throws `LeanDiscoveryError` / `ERR_LEAN_TOOLCHAIN_MISSING` with the elan install suggestion (`src/certify/discover.ts:79`). The CLI runs it first, before any theorem work (`src/cli/index.ts:449`). The non-throwing sibling `probeLeanToolchain` (`src/certify/discover.ts:114`) backs `manifest --backends`.
2. **Build placeholder theorems (`docToTheorems`, `src/cli/index.ts:794`).** No doc→Lean semantic encoder exists, so each requirement maps to a trivial kernel-decidable placeholder `True` theorem keyed by its sanitized UUID. The resulting `FND_CERTIFIED` finding states plainly it attests only that the toolchain ran and the file elaborates, NOT requirement semantics (`src/cli/index.ts:462`).
3. **Emit theorems (`emitLeanFile`, `src/certify/emit.ts:85`).** Batches every theorem into ONE self-contained `.lean` file so Lean startup is paid once; validates each name is a valid unique Lean identifier and dedupes imports.
4. **Append axiom prints.** `withAxiomPrints` appends one `#print axioms <name>` per theorem so the run also captures kernel-checked axiom provenance (`src/certify/run.ts:314`, `src/certify/run.ts:187`).
5. **Run against a scratch file.** The source is written to a throwaway temp dir removed in a `finally`, so a failed run never leaves a half-written artifact (`src/certify/run.ts:316`, `src/certify/run.ts:327`).
6. **Invoke `lean --json` (`runLean`, `src/certify/run.ts:209`).** `spawn('lean', ['--json', filePath])`, collecting stdout. It never throws on a non-zero Lean exit (the expected "certification failed" path) — it only rejects if the process cannot be spawned.
7. **Parse NDJSON (`parseLeanNdjson`, `src/certify/run.ts:76`).** One JSON object per non-blank stdout line; non-diagnostic lines go to `unparseable` rather than crashing.
8. **Map the verdict (`mapLeanResult`, `src/certify/run.ts:117`).** `certified` iff exit code is 0 AND no `severity: "error"` diagnostic — both signals checked so a future Lean release still fails safe.
9. **Extract axiom provenance (`extractAxiomProvenance`, `src/certify/run.ts:159`).** Reads only `information` diagnostics matching Lean's two `#print axioms` shapes.
10. **Retain artifact only on success.** ONLY where `certified` is true, write the `.lean` file and a `lean-toolchain` pin (`leanprover/lean4:v<version>`) into `outDir` as a re-checkable, committable artifact (`src/certify/run.ts:333`, pin builder at `src/certify/run.ts:258`). An uncertified run returns the verdict + diagnostics + axioms with no `artifact`.

## Semantic model load + inference

Lazy, offline-by-default, and reached only via `check --semantic` → `findSimilarSemantic` / `buildSimilarityGraph` → an injected `Embedder`. The embedder is built by `loadEmbedder` (`src/formal/embed.ts:205`).

1. **Resolve the flag.** `allowRemote` = explicit option, else `SYMSPEC_EMBED_ALLOW_REMOTE=1`; model defaults to the pinned `Xenova/bge-base-en-v1.5` (`src/formal/embed.ts:206`, `src/formal/embed.ts:40`).
2. **Build the pipeline.** `ensureModelAssets(allowRemote)` resolves the three pinned assets (`src/formal/model-cache.ts:177`): each is read from the OS cache dir and sha256-verified; on a miss with `allowRemote`, `fetch` from the frozen HF revision, sha256-verify, and atomically publish; on a miss while offline, throw `ModelAssetsUnavailableError` (`src/formal/model-cache.ts:155`). Then lazily `import('onnxruntime-web')` + `import('@huggingface/tokenizers')`, pin the WASM EP single-threaded, and create the `InferenceSession` (`src/formal/embed.ts:125`).
3. **Error contract.** Any factory failure is normalized by `loadEmbedder` to `EmbedModelMissingError` / `ERR_EMBED_MODEL_MISSING`, carrying a download suggestion (`src/formal/embed.ts:215`, class at `src/formal/embed.ts:46`). It never blocks the SMT/lint tiers.
4. **Inference + pool.** Tokenize, right-pad to the batch's longest sequence (truncated to `MAX_SEQ_LEN` 512), run the session, then CLS-pool the `[CLS]` token and L2-normalize so a dot product IS cosine (`src/formal/embed.ts:185`).
5. **Consume (`findSimilarSemantic`, `src/formal/semantic.ts:76`).** Embeds every response once, then for each same-system pair whose response atoms did NOT already unify computes `cosine` and, at ≥ threshold (default 0.82), emits an info-tier `FND_SIMILAR_SEMANTIC` suggesting a `glossary add` merge — propose-only, never a verdict.

## Adversarial detection harness

`runHarness` in `adversarial/harness.ts:75` (161 LOC) is the autonomous "prove it catches increasingly subtle bad specs" loop: escalate → detect → score → record, no human in the loop per round.

1. **Optionally load the embedder.** With `--semantic`, `loadEmbedder` is called once up front; if the model is unavailable it logs a note and leaves `embedder` undefined so semantic-dependent cases can be skipped rather than failing the run (`adversarial/harness.ts:79`).
2. **Escalate tier by tier.** For each tier 1..`maxTier`, `generateCases(tier)` produces one deterministic labelled case per defect kind — `contradiction`, `numeric`, `temporal`, `ambiguity`, `missing-link` — offset by seed for variety (`adversarial/harness.ts:93`; generator at `adversarial/generate.ts:335`, kinds at `adversarial/generate.ts:323`). Cases whose ONLY expected codes are embedding-tier (`FND_MISSING_TRACE_LINK`/`FND_SIMILAR_SEMANTIC`) are skipped when no model is loaded (`adversarial/harness.ts:101`).
3. **Score each case (`scoreCase`, `adversarial/harness.ts:34`).** Runs `runCheck` over the fixture (passing `{ semantic: { embedder } }` when available), then scores DETECTION (any expected `FND_*` code fired) and LOCALIZATION (a fired finding names ALL planted culprit ids, order-free) (`adversarial/harness.ts:42`, `adversarial/harness.ts:45`).
4. **Record the gap report.** Each tier row tallies `total`/`detected`/`localized`/`misses`; misses accumulate into a cross-tier `gaps` list naming which defect classes evaded detection (`adversarial/harness.ts:107`).
5. **Regression floor (`main`, `adversarial/harness.ts:118`).** The CLI entry prints the scoreboard + gap report and exits non-zero if tier-1 (blatant, model-free) detection is below 100% (`adversarial/harness.ts:150`). Run: `pnpm exec tsx adversarial/harness.ts [--max-tier N] [--semantic]`.

## Pinned red-team eval rounds (regression fixtures)

`evalRoundCases()` in `adversarial/eval-rounds.ts:70` pins the winning rounds of a real external red-team eval — an Opus 4.8 proposer against a blind judge panel with z3 as the oracle. The timeline: the proposer beat an earlier symspec 25/30 under `--strict`, then 28/30 after the first hardening; the last two escapes were the numeric tier's structural blind spot (a bound keyed off the verb phrase, an aggregate never summed, an emergent impossibility no lexicon reaches), which issue #2 closed. Each fixture carries an `expectedCodes` list; a case with codes is a PROOF case, an empty list is an ABSTENTION case (`adversarial/eval-rounds.ts:70`).

`adversarial/__tests__/eval-rounds.test.ts:48` enforces them under `--strict --semantic --temporal` with three `it`/`it.each` blocks:

1. **Proof cases** assert `FND_CONTRADICTION`/`FND_NUMERIC_CONTRADICTION` fires, names ALL planted culprits, and pushes `counts.error > 0` (`adversarial/__tests__/eval-rounds.test.ts:53`).
2. **Abstention cases** assert no `FND_CONTRADICTION`, `verified === false`, `strictGate === 'fail'`, and a non-empty `coverage.demotions` where every demotion carries an actionable `action` (`adversarial/__tests__/eval-rounds.test.ts:72`).
3. **The win-condition guard** asserts the eval's exit-0 shape (no errors AND strict not failing) is unreachable on every round (`adversarial/__tests__/eval-rounds.test.ts:89`).

The reproducer-a pair proves the full propose→decide loop end to end: an abstention fixture (candidate demotes) plus a committed-glossary fixture where the numeric tier then proves the conflict (`adversarial/eval-rounds.ts:589`).
