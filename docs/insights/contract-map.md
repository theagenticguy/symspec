# symspec · Contract map

What each module assumes about its neighbor across the load-bearing boundaries. Each section names the **producer** (what B guarantees), the **consumer** (what A relies on), the **shape** (the cited type or invariant), and what **enforces** it (a type or a test).

## CLI → pipeline

**Producer (`pipeline/check.ts`).** `runCheck(doc, options)` is the whole default linter loop: it wires Tier-0 structural, GtWR/free lint, the always-on ambiguity family, and the SMT/numeric/temporal/graph formal tiers into one report and returns a `Promise<CheckReport>` (`src/pipeline/check.ts:311`). The result shape is fixed and now richer: `findings`, `excluded`, `pairsChecked`, `waived`, `counts`, plus the issue-#2 additions `residualRisk`, `coverage`, `verified`, and the opt-in `strictGate` (`src/pipeline/check.ts:324`). Each `CheckFinding` carries a stable `code`, `severity`, `tier`, `requirementIds`, `message`, and optional `span`/`suggestion`/`evidence` (`src/pipeline/check.ts:111`).

**Consumer (`cli/index.ts`).** The CLI is "the thin formatter over the library API" (`src/cli/index.ts:2`). The `check` action builds `CheckOptions` from raw string flags via `buildCheckOptions` (`src/cli/index.ts:1184`), calls `runCheck`, and wraps the report verbatim in a `success('check', {...})` envelope (`src/cli/index.ts:634`). It never reshapes findings; it only spreads in the CLI-owned extras.

**Shape / invariant.** `CheckOptions` is the contract surface: `similarityThreshold?`, `timeoutMs?`, `solverBudgetMs?`, the opt-in `semantic?: { embedder; threshold? }` / `temporal?: { bound? }`, and the coverage gates `strict?` / `failOnUnmatched?` (`src/pipeline/check.ts:126`). The CLI sets `semantic` by lazy-loading the embedder (`src/cli/index.ts:543-548`). `buildCheckOptions` types itself against `NonNullable<Parameters<typeof runCheck>[1]>` (`src/cli/index.ts:1189`), so a drifted option shape is a compile error. Severity `counts` plus `strictGate`/`verified` are the input to the exit-code contract — the CLI's `exitCodeForEnvelope` reads them (`src/cli/index.ts:154`).

**Enforced by.** The `Parameters<typeof runCheck>` type binding on `buildCheckOptions` (compile-time). Behavior of the wired pipeline is covered by `src/pipeline/__tests__/check.test.ts` and the CLI path by `src/cli/__tests__/integration.test.ts`.

## pipeline → gate

**Producer (`pipeline/gate.ts`).** `gateRequirements(requirements, waivers)` partitions a requirement set into `{ included, excluded }` (`src/pipeline/gate.ts:164`). A statement is excluded when it has an `error`-severity GtWR finding (reason `'blocking-surface-check'`) or a marked parse failure (reason `'parse-failure'`); only `error`-severity findings block — `warn`/`info` never exclude (`src/pipeline/gate.ts:39`, `:98-103`). The gate is pure and deterministic (`src/pipeline/gate.ts:30`).

**Waiver-aware re-admission (the waiver↔gate contract).** The gate takes an optional `waivers` list; a blocking finding suppressed by a committed waiver no longer excludes its requirement, so a requirement whose ONLY blocking finding is waived is RE-ADMITTED to the formal tier — `src/pipeline/gate.ts:98-103`, `:120-133`. This closes a silent unsoundness: previously `check` waived a formal-blocking finding out of `findings[]` (and the exit gate) but the gate still excluded the requirement, so the author saw the finding "resolved" while the solver silently never reasoned about it. `isWaivedBlocking` (`src/pipeline/gate.ts:80`) is kept deliberately in sync with `isWaived` in `check.ts` (`src/pipeline/check.ts:453`) — the same finding must both drop from the report AND stop excluding, or the two disagree. Waivers default to empty, so a caller passing none gets the exact pre-feature partition.

**Consumer (`pipeline/check.ts`).** `runCheck` computes `gateResult = gateRequirements(requirements, doc.waivers ?? [])` and `excluded = excludedIds(gateResult)` (`src/pipeline/check.ts:708-709`), and inside the formal callback filters the solver's requirements and pairs down to the included set before any encoding. The `--emit-smt2` export path reuses the SAME waiver-aware gate so the artifact is a faithful export of what `check` evaluates (`src/pipeline/check.ts:595`). The excluded set is surfaced via `CheckReport.excluded` AND drives one `FND_EXCLUDED_FROM_FORMAL` per excluded requirement plus a `verified` demotion (see the coverage/demotion contract below).

**Shape / invariant.** The SMT layer never receives unsound input — the propositional formal tier only ever sees `included`. This is the forced pipeline order parse → lint → symbolize → solve. Note the deliberate exception: the numeric tier (`src/pipeline/check.ts:822`) and the temporal tier (`src/pipeline/check.ts:871`) run over ALL requirements, not the gate-included subset, because numeric/temporal consistency is independent of the propositional-encoding soundness the gate protects — a lint-blocking finding must not hide a real numeric or temporal contradiction.

**Enforced by.** `src/pipeline/__tests__/gate.test.ts` (partition correctness, severity gating, waiver re-admission); the pure-determinism assumption is stated at `src/pipeline/gate.ts:30`.

## propose signals → check demotion (the demotion-only coverage contract)

This is the inter-module spine of the issue-#2 hardening. **Two producers emit info-only findings; one consumer classifies them and can only DEMOTE `verified`, never promote it.**

**Producers (`formal/quantity-alias.ts`, `formal/relational.ts`).** `findQuantityAliasCandidates` emits `FND_QUANTITY_ALIAS_CANDIDATE` for same-system+same-trigger opposed numeric bounds whose labels share an object suffix but differ in verb, carrying the exact `glossary add` command (`src/formal/quantity-alias.ts:160`). `findRelationalUnchecked` emits `FND_RELATIONAL_UNCHECKED` for the aggregate/relational structural shape under a shared trigger (`src/formal/relational.ts:100`). Both are info-severity and never assert a conflict. They are wired into the formal closure over ALL requirements (`src/pipeline/check.ts:835`, `:856`), reusing the predicates and atom-owner roster already built for the numeric/propositional tiers.

**Consumer (`pipeline/check.ts`).** Two sets classify these codes: `PROPOSE_ONLY_FND_CODES` (`src/pipeline/check.ts:413`) bars them from counting toward `verified` and from participating as decide-tier findings; `COVERAGE_GAP_FND_CODES` (`src/pipeline/check.ts:441`) additionally bars them from suppressing the `FND_NO_PAIRS_CHECKED` disclaimer via the `crossRequirementFired` predicate (`src/pipeline/check.ts:1085`) — each signals a comparison did NOT happen, so counting it as "a comparison happened" would let the report both claim nothing was compared and hide the finding that says so (an internal contradiction the adversarial review caught). Each kept propose-only coverage finding appends a `CoverageDemotion` with a discharging `action` (`src/pipeline/check.ts:1234`, `:1248`); `verified = demotions.length === 0` (`src/pipeline/check.ts:1289`).

**Shape / invariant — demotion-only.** `CoverageDemotion.reason` is a closed union: `uncovered-requirement | open-opposition-candidate | no-decide-tier-comparison | semantic-tier-skipped | excluded-from-formal | quantity-alias-candidate | relational-reasoning-not-attempted` (`src/pipeline/check.ts:252`). Propose-only findings and coverage stats can push `verified` toward `false` but NEVER toward `true` — the dual of the propose/decide split. Two demotions are keyed off the STRUCTURAL fact, not the post-waiver finding set, so a waiver cannot promote: `excluded-from-formal` reads `gateResult.excluded` directly (waiving the disclosure hides the line but the solver still never saw the requirement — `src/pipeline/check.ts:1191`, `:1219`). Quantity-alias and relational demotions ARE keyed off the kept set on purpose — those ARE legitimately triaged away by a waiver (the author confirmed the quantities differ, or hand-verified the aggregate) — `src/pipeline/check.ts:1197`.

**Enforced by.** `adversarial/__tests__/eval-rounds.test.ts` (the abstention cases assert `verified === false`, `strictGate === 'fail'`, and ≥1 actionable demotion; proof cases assert the culprit-naming contradiction fires — the reproducer-a pair proves the full loop abstain → commit alias → z3 proves it); `src/pipeline/__tests__/check.test.ts`.

## check → solvers (the injected FormalTier closure)

**Producer (`solvers/index.ts`).** `runSolvers(doc, opts)` always runs the free tier (exact duplicates, weasel-word ambiguity, the pairwise candidate filter) and, when `opts.formal` is present, invokes an INJECTED formal closure (`src/solvers/index.ts:68-90`). The contract types are `FormalTierInput = { reqs: readonly ReqView[]; pairs: readonly CandidatePair[] }` and `FormalTierResult = { findings: SolverFinding[]; pairsChecked: number }`, with `FormalTier = (input) => Promise<FormalTierResult>` (`src/solvers/index.ts:32-52`). The tier is injected rather than imported specifically so `solvers/` stays free of a static `../formal/*` dependency (which would cycle, since `formal/*` imports `./types.js`) and so tests can stub it (`src/solvers/index.ts:16-22`, `:47-52`).

**Consumer (`pipeline/check.ts`).** `runCheck` supplies the real Z3-backed closure (`src/pipeline/check.ts:734`). The closure captures its rich, FND-coded, evidence-carrying findings in a `check.ts`-local array and returns `{ findings: [], pairsChecked: includedPairs.length }` back to the orchestrator — reporting an empty `findings` deliberately, so nothing is double-counted between the `SolverReport` projection and the rich findings pushed later (`src/pipeline/check.ts:1004`).

**Shape / invariant.** The closure owns all formal work: it obtains one context (`getContext('symspec-check')`, `src/pipeline/check.ts:751`), gate-filters, encodes once, and fans out to contradiction/subsumption/vacuity/completeness/similar/needs-review (over the included set), numeric (over all reqs), the propose-only quantity-alias + relational detectors (over all reqs), temporal (over all reqs, when opt-in), and semantic+graph (when `--semantic`). `pairsChecked` counts only the included candidate pairs the pairwise checks evaluated.

**Enforced by.** The `FormalTier` function type (compile-time decoupling); `src/pipeline/__tests__/check.test.ts` and `src/solvers/__tests__` cover the free-tier-alone path and the injected path.

## formal encode → backend

**Producer (`formal/encode.ts`).** `encode(req, atomize)` returns an `EncodedRequirement` whose `formula` is the guarded implication `guard ⇒ body`, where `guard` is the requirement id verbatim (so an unsat core names the culprit ids) and `body` is `context ⇒ response` (or a bare `response` for ubiquitous) (`src/formal/encode.ts:205-243`). The `Formula` is a plain-data, Z3-free AST — `atom | not | and | or | implies | cmp`, where `cmp` is the arithmetic-comparison node the numeric tier builds (`src/formal/encode.ts:97-116`). `encode` is pure and never touches `z3-solver` (`src/formal/encode.ts:31-46`). `materialize(ctx, f)` lowers a `Formula` into a `z3-solver` `Bool` by structural recursion — the `cmp` case lowers to a `Real` comparison over a per-quantity variable (`src/formal/encode.ts:260-290`).

**Consumer (`formal/backend.ts` + solver/numeric/temporal tiers).** `backend.ts` owns the one-time WASM init and hands back a fresh named `Z3Context` via `getContext(name)`; the `init()` promise is memoized so concurrent callers share one WASM instantiation (`src/formal/backend.ts:58`, `:36`). `materialize` depends only on the *shape* `Z3Context` (`ctx.Bool.const`, `ctx.Real.const`, `ctx.Not/And/Or/Implies`) — `Z3Context = ReturnType<Z3Module['Context']>` (`src/formal/backend.ts:34`). Every solver-driving tier calls `materialize` then `check()`; `numeric-contradiction.ts` and `temporal.ts` both reuse `materialize` and the identical requirement-id-as-guard technique (`src/formal/numeric-contradiction.ts:87`, `src/formal/temporal.ts:126`).

**Shape / invariant.** The Formula AST + the guard-implication shape is the contract. Two boundaries hold: (1) encoding is pure/synchronously testable with no WASM boot, and materialization is a *separate* step the solver tiers call; (2) atomization is injected, not imported — `encode` depends on the `Atomize` function type, never on `atomize.ts` (`src/formal/encode.ts:81`).

**Enforced by.** `src/formal/__tests__/encode.test.ts` (per-pattern formula shape, purity, the `cmp` node) and `src/formal/__tests__/backend.test.ts` (WASM init, availability probe).

## atomize → glossary → semantic (the propose/decide determinism contract)

This is the spec's designated load-bearing boundary. **Two halves that must never cross: embeddings PROPOSE, the committed glossary DECIDES.**

**Producer — DECIDE (`formal/atomize.ts`).** `atomize(args)` is the single pure function turning an EARS slot into a scoped Boolean `Atom` (`src/formal/atomize.ts:135`). It guarantees four tested invariants (`src/formal/atomize.ts:11-44`): purity/determinism, conservative near-exact normalization (lowercase → strip one leading article → strip punctuation → underscore-join; no stemming — `src/formal/atomize.ts:120-125`), per-`systemName` scoping (`sys__<system>__<kind>__<body>`, `src/formal/atomize.ts:164`), and negation-on-the-same-atom (polarity composed by XOR with the antonym-table flip — `src/formal/atomize.ts:153-162`). Glossary canonicalization runs **first**, before antonym unification (`src/formal/atomize.ts:144-147`). `glossaryIndex(entries)` builds the normalized alias→canonical map `atomize` consumes (`src/formal/atomize.ts:96`).

**Consumer / Producer — PROPOSE (`formal/semantic.ts`).** `findSimilarSemantic` embeds response phrasings and, for same-system pairs whose atoms did **not** already unify, emits an info-tier `FND_SIMILAR_SEMANTIC` finding *suggesting* a `symspec glossary add` merge (`src/formal/semantic.ts:76`). It "NEVER emits a conflict verdict — its only durable effect is a suggestion the calling agent may confirm into the glossary" (`src/formal/semantic.ts:9-12`). It consults `atomize` to skip already-unified pairs (`atomA.name === atomB.name`, `src/formal/semantic.ts:103`) and respects the same per-system scoping.

**Shape / invariant — the propose/decide split.** The deterministic SMT verdict path consults *only* the committed glossary, never the embedding model (`src/formal/embed.ts:30-33`). The fuzzy embedding step only PROPOSES entries; the deterministic `glossaryIndex` lookup inside `atomize` is what actually merges them. The DECIDE half is the CLI `glossary add|remove|list` command; confirming an entry there is what changes a verdict. Given `(doc + committed glossary + pinned model)` the run is reproducible — determinism lives entirely on the DECIDE side.

**Enforced by.** `src/formal/__tests__/atomize.test.ts` (the four invariants), `src/formal/__tests__/semantic.test.ts` (propose-only, skip-already-unified, same-system-only), and `src/pipeline/__tests__/check-semantic.test.ts` (the opt-in path).

## embed → model-cache (the embedder pooling contract)

**Producer (`formal/model-cache.ts`).** `ensureModelAssets(allowRemote)` returns digest-verified absolute local paths — `{ modelPath, tokenizerPath, tokenizerConfigPath }` (`src/formal/model-cache.ts:177`). Every asset is fetched from one frozen HuggingFace revision (`MODEL_REVISION`, `src/formal/model-cache.ts:41`) and checked against a hardcoded sha256; a silent upstream change or corrupt download fails the digest check rather than poisoning embeddings (`src/formal/model-cache.ts:12-18`). `allowRemote` defaults OFF: a cache miss with remote disabled throws `ModelAssetsUnavailableError`.

**Consumer (`formal/embed.ts`).** `loadEmbedder` depends on `ensureModelAssets` returning those verified paths — the default pipeline factory calls it first, then reads the three files (`src/formal/embed.ts:205`). Any factory failure (cache miss, offline, corrupt) is normalized to the one contract `EmbedModelMissingError` → `ERR_EMBED_MODEL_MISSING` (`src/formal/embed.ts:45`). The model load never blocks the SMT/lint tiers — it is opt-in via `check --semantic` (`src/formal/embed.ts:22-26`; CLI lazy-load at `src/cli/index.ts:362-363`).

**Shape / invariant — the pooling contract.** `Embedder = (texts) => Promise<Float32Array[]>` (`src/formal/embed.ts:64`). The returned vectors are **CLS-pooled** (the `[CLS]` token at sequence position 0) and **L2-normalized**, matching how BGE was trained, "so a plain dot product IS cosine similarity" (`src/formal/embed.ts:9-12`). The pipeline pools + normalizes internally with `{ pooling: 'cls', normalize: true }` (`src/formal/embed.ts:221`). Because of that, `cosine(a, b)` is a bare dot product with no re-normalization (`src/formal/embed.ts:231`) — and BOTH `semantic.ts` (`src/formal/semantic.ts:111`) and `graph.ts`'s inlined `dot()` (`src/formal/graph.ts:89-95`) rely on this equivalence. If the embedder ever returned un-normalized vectors, both consumers would silently be wrong.

**Enforced by.** `src/formal/__tests__/model-cache.test.ts` (digest verification, offline throw, atomic publish) and `src/formal/__tests__/embed.test.ts` (CLS pooling, L2 normalization, dot==cosine, missing-model error mapping).

## embedder → graph (the deterministic PROPOSE-only graph tier)

**Producer (`formal/embed.ts`).** The same `Embedder` closure and pooling/normalization guarantee described above — L2-normalized CLS vectors such that dot product equals cosine.

**Consumer (`formal/graph.ts`).** `buildSimilarityGraph(reqs, embedder, opts)` (`src/formal/graph.ts:102`) embeds each requirement's rendered text, computes all-pairs cosine via the inlined `dot()` (`src/formal/graph.ts:89`), and emits propose-only info findings: `FND_MISSING_TRACE_LINK` for high-cosine unlinked pairs (`src/formal/graph.ts:151`) and `FND_DUPLICATE_CLUSTER` for ≥3-member connected components (`src/formal/graph.ts:229`). `check.ts` supplies the `GraphRequirement` projection, deriving `linkedTo` from the doc's committed `refines`/`derives`/`satisfies` edges (`src/pipeline/check.ts:919-920`), and runs it only under `--semantic` reusing the same injected embedder as the paraphrase pass.

**Shape / invariant — determinism is engineered so the tier can be always-on-when-semantic.** Cosine is QUANTIZED to a fixed precision before any threshold comparison so sub-ULP jitter can never flip an edge; neighbor ties break on requirement id (a total order); clustering is union-find over the deterministic edge set (`src/formal/graph.ts:16-27`, `:81-95`, `:176-238`). Given `(doc + pinned model)` the graph, clusters, and findings are byte-identical across runs. Every finding is `info` and PROPOSES an edge an agent confirms into the committed DAG — the deterministic SMT/structural tiers read only committed edges, never these proposals (`src/formal/graph.ts:8-13`).

**Enforced by.** `src/formal/__tests__/graph.test.ts` (determinism, quantization, kNN pruning, cluster detection, missing-link vs already-linked); `src/pipeline/__tests__/check-semantic.test.ts` (the opt-in wiring).

## numeric extraction → numeric-contradiction (the arithmetic conflict tier)

**Producer (`formal/numeric.ts`).** `extractNumericPredicates(text, systemName, quantityAliases?)` lifts each numeric bound in a slot into a typed `NumericPredicate = { quantity, label, comparator, value, baseUnit, sourceText }` (`src/formal/numeric.ts:240`). Two guarantees are load-bearing: quantity identity — "temperature"/"the temperature"/"temp" collapse to one canonical per-system key `sys__<system>__qty__<label>` (`src/formal/numeric.ts:160`), mirroring atom scoping so two systems' "latency" stay distinct; and unit normalization — values normalize into a canonical base (ms, B) via `DIMENSIONS` before comparison (`src/formal/numeric.ts:64`). The optional `quantityAliases` is the committed glossary as a normalized-label → canonical-label map (DECIDE side): it canonicalizes the label BEFORE keying so two phrasings of one quantity the author has confirmed collapse to one key (`src/formal/numeric.ts:160-170`); omitted ⇒ byte-identical to before. The key deliberately does NOT strip trailing comparator words — the soundness comment at `src/formal/numeric.ts:211` (a conservative key can only MISS; stripping fabricated a false verdict). Extraction is pure regex/lexicon, deterministic, and returns `[]` when nothing matches — a miss is an honest false negative, never a fabricated constraint (`src/formal/numeric.ts:21`). `DIMENSIONS` + the `Dimension` type are exported for the manifest's units disclosure (`src/formal/numeric.ts:52`, `:64`).

**Consumer (`formal/numeric-contradiction.ts`).** `findNumericContradictions(ctx, reqPreds)` groups predicates by canonical quantity, skips any quantity constrained by fewer than two distinct requirements, asserts each predicate under its requirement-id guard, and asks Z3 for joint satisfiability (`src/formal/numeric-contradiction.ts:55-92`). On `unsat` it maps the unsat core back to requirement ids (dequoting Z3's `|...|` symbols), minimizes by deletion so an innocent requirement sharing the quantity cannot ride along, and emits `FND_NUMERIC_CONTRADICTION` (`error`) carrying `evidence.numeric` — the shared quantity plus each culprit's normalized `(comparator, value, unit)` (`src/formal/numeric-contradiction.ts:99-129`). `check.ts` builds `reqPreds` by extracting over `systemResponse` + `trigger` + `preCondition` for ALL requirements, passing the committed glossary as the `quantityAliases` map (`src/pipeline/check.ts:810-821`).

**Shape / invariant.** LIA/LRA is convex + decidable, so the verdict and unsat core are reproducible — this tier is verdict-eligible (`error`), unlike the fuzzy propose-only tiers (`src/formal/numeric-contradiction.ts:19-24`). The `evidence.numeric` shape is a distinct branch on the shared `Evidence` type, present only for this tier (`src/formal/finding.ts:79-95`); propositional checks leave it absent and carry the atom table + core instead.

**Enforced by.** `src/formal/__tests__/numeric.test.ts` (extraction determinism, quantity/unit normalization, comparator longest-match), `src/formal/__tests__/numeric-contradiction.test.ts` (joint-UNSAT, core minimization), and `src/pipeline/__tests__/check-numeric.test.ts` (the always-on wiring over all requirements).

## temporal-patterns → temporal (bounded LTL→SMT lowering)

**Producer (`formal/temporal-patterns.ts`).** `earsToTemporal(req)` is the pure, solver-free front half: it maps each EARS pattern to a Dwyer/SPS/FRET LTL shape over the `TemporalFormula` AST — event-driven → `G(trig → F resp)`, unwanted-behavior → `G(trig → ¬resp)`, state-driven → `G(state → resp)`, optional-feature → `G(feature → resp)`, ubiquitous → `G(resp)` (`src/formal/temporal-patterns.ts:168-195`). The switch is exhaustive over `EarsPattern`. Response polarity is threaded onto the response literal via the `negated` flag (never a substring of the atom name), and atom names use a self-contained scoping normalizer that deliberately mirrors `atomize.ts`'s rules — WITHOUT importing it — so a temporal atom and its propositional counterpart line up by name (`src/formal/temporal-patterns.ts:25-40`, `:121-134`).

**Consumer (`formal/temporal.ts`).** `findTemporalContradictions(ctx, reqTemporals, k)` lowers each formula to per-timestep Bools (`<atom>@<t>`) via `lowerAt` — `G` unrolls to a bounded conjunction, `F` to a bounded disjunction, `X` shifts one step (false past the horizon), `U` to its bounded expansion (`src/formal/temporal.ts:62-102`) — asserts each requirement's encoding under its id guard, adds an `F(antecedent)` reachability assertion per distinct guarded trigger so `G(ante → cons)` is not vacuously satisfiable (`src/formal/temporal.ts:186-206`), and checks joint satisfiability. `check.ts` builds `{ id, formula: earsToTemporal(r) }` for ALL requirements when `--temporal` is set (`src/pipeline/check.ts:871-877`).

**Shape / invariant — sound-for-UNSAT, not complete-for-SAT.** The loop-free encoding means an `unsat` verdict at bound `k` is a genuine temporal contradiction (safety/response obligations only get harder with more steps), but a `sat`-at-`k` is NOT a consistency certificate — a conflict may first appear past the horizon. A finding is emitted ONLY on `unsat`, so the tier never over-reports; the evidence records `{ bound: k, complete: false }` (`src/formal/temporal.ts:13-32`, `:143`). Culprit ids come from a deletion-minimized, dequoted unsat core (`src/formal/temporal.ts:131-133`), the same technique the propositional and numeric tiers use.

**Enforced by.** `src/formal/__tests__/temporal-patterns.test.ts` (per-pattern LTL shape, polarity threading, scoping parity), `src/formal/__tests__/temporal.test.ts` (lowering of each modality, sound-for-UNSAT, antecedent reachability, core minimization). The Z3-WASM bounded-response feasibility is CI-gated by `scripts/temporal-feasibility.ts`.

## CLI → manifest (single-source, no-drift)

**Producer.** Three single-source corpora feed the two agent-facing surfaces: `COMMAND_DESCRIPTIONS`/`COMMAND_SUMMARIES` (the what/when/returns/idempotency prose, `src/cli/descriptions.ts:55`), `COMMAND_SPECS` (the command inventory + per-command Zod argument object, `src/cli/manifest.ts:229`), and `EnvelopeTypeSchema` (the closed, append-only set of envelope `type` discriminants, `src/cli/types-enum.ts:54`). Argument descriptions in the manifest are the byte-for-byte `.describe()` corpus of the runtime-validating Zod fields — "the transcription IS the schema" (`src/cli/manifest.ts:10-16`, `:370`).

**Consumer.** `cli/index.ts` wires the full `COMMAND_DESCRIPTIONS[name]` text into each Commander `.description()`; `manifest.ts` reads `COMMAND_SUMMARIES[c.name]` for each entry's summary and derives the `types` table from `EnvelopeTypes` (`src/cli/manifest.ts:402`). `scripts/gen-agents.ts` calls `buildManifest()` and renders its command + code tables into `AGENTS.md` (`scripts/gen-agents.ts:23`, `:91`, `:133-141`), so the generated agent doc cannot drift from the manifest. The success `type` of a command IS its command name (`src/cli/types-enum.ts:19-25`). A fourth derived corpus: the manifest's `units` section is built from the `DIMENSIONS` table in `formal/numeric.ts` — never a hand-list — so a unit added to the numeric tier surfaces to agents authoring bounds automatically (`src/cli/manifest.ts:59`, `ManifestUnitsSchema` `:504`, doc `:487`).

**Shape / invariant.** The three corpora must stay synced: adding a command without its `EnvelopeType` (or vice versa), or letting a manifest description diverge from the Zod field, is drift. The envelope `type` enum is append-only — never remove/rename/reorder a shipped member. `buildManifest()` is pure and byte-stable (`src/cli/manifest.ts:389`).

**Enforced by.** `src/cli/__tests__/types-enum.test.ts` asserts every `COMMAND_SPECS` name is an `EnvelopeType` member and every non-`'error'` member is a real command (`:94`), that `manifest().types` equals `EnvelopeTypes` (`:99`), and the append-only snapshot (`:58`). `src/cli/__tests__/manifest.test.ts` asserts manifest argument descriptions are byte-for-byte the `.describe()` metadata (`:62-97`) and the code-catalog descriptions match `ErrCodeMeta`/`GtwrCodeMeta`/`FndCodeMeta`. The `AGENTS.md` drift gate is `pnpm check:agents` (`package.json:49`).
